# 결과 설명자료

> 이 문서의 숫자는 `python tools/build_plan.py`를 실행하면 실제 자료로 다시 계산돼요. 기획서와 같은 숫자예요.

## 1. 문제 정의

밤에 버스에서 내린 사람은 대부분 걸어서 집까지 가요. 그래서 **밤길은 정류장에서 시작돼요.**

그런데 지금은 이런 질문에 답해 주는 곳이 없어요.
- "우리 애가 밤 10시에 내리는 정류장 근처에 CCTV나 비상벨이 있을까?"
- "예산이 1억원이면 어디에 무엇을 달아야 가장 많은 주민을 지킬 수 있을까? 건의서에 쓸 근거가 필요해."

필요한 자료는 여기저기 흩어져 있어요. 버스 이용은 제주빅데이터센터와 제주데이터허브에, CCTV·비상벨·학교 위치는 공공데이터포털에 있어요. 이걸 하나로 합치려면 아이디와 좌표를 맞추고 거리를 계산해야 해서, 도민이 직접 하기는 어려워요. 비어 있는 곳을 찾았다 해도 **"그럼 어디에, 무엇을, 몇 대 달아야 하지?"**는 또 따로 계산해야 해요.

**안심하차 Agent는 흩어진 자료를 하나로 합치고, 계산하기 전에 자료를 먼저 살펴보고, 정해진 예산으로 가장 많은 사람을 지킬 수 있는 설치 계획까지 알려줘요.** 예를 들어 제주시 공개 CCTV 382곳이 모두 교통용으로 올라와 있다는 걸 Agent가 알아채고, 용도와 상관없이 모든 CCTV를 세도록 계산 방법을 바꿔요.

## 2. Agent 구조

```
[도민의 질문] ─▶ ① 질문 이해 (동네, 시간, 대상, 설치 대수)
                 ② inspect_data        어떤 자료인지 알아보고 위치·이름을 맞춤
                 ③ check_coverage      자료가 한쪽에 몰려 있지 않은지 살핌 ──▶ 계산 방법 결정
                 ④ run_gap_analysis    정류장마다 이용하는 사람과 주변 CCTV·비상벨 계산 (학생 질문이면 학교 근처만)
                 ⑤ check_robustness    기준을 바꿔 한 번 더 계산 ──▶ 정류장마다 "기준 바꿔도 n/4"
                 ⑥ plan_installations  한 대로 옆 정류장까지 가장 많은 사람을 지키는 위치를 차례로 고름
                 ⑦ look_up_place       질문에 나온 동네 주변 정류장 찾기
                 ⑧ finalize_report     작은 숫자 가리기, 고치는 방법, 근거, 건의 문장, 설치 계획 후보
               ◀─ [1순위 정류장 + 고치는 방법 + 설치 계획 + 건의서]
```

- **Claude 모드**: Claude가 결과를 보면서 다음에 어떤 계산을 할지 정하고, 마지막 설명과 건의 문장을 써요.
- **규칙 모드**: API를 쓸 수 없을 때도 같은 계산을 같은 순서로 끝까지 해요.
- 어느 모드든 **숫자는 모두 정해진 계산식으로 구해요.** Claude가 숫자를 지어내지 않아요.
- Agent가 어떤 계산을 어떤 순서로 했는지, 중간에 무엇을 판단했는지가 **Agent 분석 흐름 그림**으로 화면에 나와요.

## 3. 화면 6개

| 화면 | 할 수 있는 일 |
|---|---|
| 홈 | 서비스 소개(첫 화면, 숫자 카드, 주제를 고른 이유, Agent가 하는 일)와 **Agent 작업 공간**. 작업 공간은 왼쪽 대화창에서 평소 말로 묻고("열시 반", "연동", "우리 애", "예산 1억"), 오른쪽 밤의 제주 3D 지도에서 바로 확인해요. 처음 열면 실제 자료로 시작하고, CSV를 화면에 끌어다 놓으면 Agent가 어떤 자료인지 알아보고 무엇이 달라지는지 말한 뒤 바로 다시 분석해요 |
| 우선 개선 | **Agent가 고른 1순위 정류장**과 10곳 목록. 정류장마다 **고치는 방법**(CCTV 새로 달기 / 근처 CCTV 방향 돌리기 / 비상벨 달기), **주변 지도**(CCTV·비상벨이 닿는 범위), **걷는 시간**, 비교 숫자, 로드뷰 링크, 결과 확인 |
| 설치 계획 | 예산을 정하고 정류장마다 할 일을 고르면 몇 명을 지키는지와 등급이 바로 나오고, Agent 추천과 비교돼요. 몇 대를 달면 몇 명을 지키는지 그래프도 있어요 |
| 한눈에 보기 | 큰 숫자 4개와 꼭 알아야 할 내용 4가지 |
| Agent가 한 일 | Agent 분석 흐름 그림, 단계별 기록, Agent의 설명 |
| 건의서 | 요지·현황·우선 개선 표·위치·정류장별 건의·설치 계획안·기대 효과·확인 결과를 **그림 8개**와 함께 정리. 바로 인쇄하거나 PDF로 저장 |

### 설치 계획

| CCTV 10대를 어디에 다느냐에 따라 | 하루 이용자 |
|---|---|
| **Agent 추천 위치** (옆 정류장까지 함께) | **8,688명** |
| 이용 많은 곳부터 | 8,290명 |
| 아무 데나 (20번 평균) | 290명 |
| 외진 곳부터 | 276명 |

- Agent가 고른 곳에 달면 외진 곳부터 다는 것보다 31배 많은 사람에게 닿아요. 순위 10곳에는 없던 서귀포버스터미널(설치 순서 3번, 정류장 6곳에 함께 닿음)도 찾아내요.
- 예산 1억원 Agent 추천: 45곳을 손봐요(그중 19곳은 CCTV 방향만 돌려요). 새로 CCTV가 닿는 사람은 하루 12,689명, 가까이에 비상벨이 생기는 사람은 27,442명이에요. 같은 돈을 이용 많은 곳부터 새로 다는 데 쓰는 것보다 45% 더 많은 사람을 지켜요.
- 비용: CCTV 새로 달기 430만원(2024년 지자체 CCTV 설치 비용 2,824억원 ÷ 65,296대), 방향 돌리기 50만원, 비상벨 달기 200만원. 화면에서 바꿀 수 있어요.

이 과정에서 Agent가 직접 판단한 것:
- 허브 자료(7자리)와 정류장 자료(9자리)의 아이디가 다른 걸 알아채고 **정류장 이름으로 맞춰 연결**
- 정류장별 이용 자료가 있는 걸 보고 **이용하는 사람이 많은 정류장부터 보도록 결정**
- 제주시 CCTV가 모두 교통용으로 올라와 있는 걸 알아채고 **용도와 상관없이 모든 CCTV를 세도록 변경**
- 기준을 4가지로 바꿔 **순위가 그대로인지 다시 확인**
- "CCTV 5대", "우리 애가 학원 끝나고" 같은 질문에서 **설치 대수와 대상(학교 근처)을 알아듣고 계산 범위를 바꿈**

## 5. 실행 결과 (가상 데이터, 규칙 모드)

`python tools/make_results.py`로 똑같이 다시 만들 수 있어요. 결과 파일은 `docs/results/`에 있어요.

> 아래 결과는 **가상 데이터**로 만든 거예요. 기능을 보여주기 위한 것이고, 실제 장소에 대한 결론이 아니에요.

### 시나리오 1. "제주 전체에서 밤길 공백이 큰 정류장 10곳 알려줘"
- 정류장 407곳을 계산했어요.
- 1위는 일부러 넣어 둔 "가상신도시" 정류장이에요. 밤에 하루 평균 59.9명이 내리는데, 가장 가까운 CCTV가 451m, 비상벨이 827m 떨어져 있어요.
- 10곳 모두 100m 안에 CCTV가 없어요.

### 시나리오 2. "우리 애가 밤 10시에 노형에서 버스 내리는데, 그 근처 괜찮아?"
- Agent가 질문에서 **밤 10~11시**와 **노형**을 알아듣고 노형 주변 정류장 98곳만 봤어요.
- 1위는 가상노형정류소17이에요. 밤 10~11시에 하루 평균 37.1명이 내리고, 가장 가까운 CCTV는 154m예요.

### 시나리오 3. "애월 쪽에 CCTV나 비상벨을 먼저 놓아야 할 곳 건의서 만들어줘"
- 처음 계산해 보니 10곳 대부분이 밤에 내리는 사람이 하루 10명 미만이었어요.
- Agent가 **이대로는 순위를 믿기 어렵다고 보고, 시간을 저녁 8~11시로 넓히고 타는 기록도 더해 다시 계산**했어요.
- 1위는 가상애월정류소20이에요. 하루 평균 17.4명이 타고 내리고, 가장 가까운 CCTV가 1,363m예요. 마지막 버스 이용이 밤 9시대라 막차가 이른 곳으로도 나왔어요.

## 6. 확인 방법

| 확인한 것 | 방법 | 결과 |
|---|---|---|
| 좌표 변환 | 위경도 → TM → 위경도로 바꿔 오차 확인 (3개 좌표계, 제주 3지점) | 1cm 미만 |
| 정답을 아는 가상 자료 | 이용이 많고 CCTV가 적은 "가상신도시"를 넣어 두고 위로 올라오는지 확인 | 1위 |
| 순위 (기준) | CCTV 50·150m, 비상벨 100·300m로 다시 계산 | 평균 7.0/10 그대로, 4곳은 늘 10위 안 |
| 순위 (기간) | 하루치·13일치·25일치 10곳 비교 | 하루치와 9/10, 13일치와 10/10 같음 |
| 설치 위치 | 작은 예제로 옆 정류장 계산 확인, 실제 자료로 이용 많은 곳부터·외진 곳부터·아무 데나와 비교 | 이용 많은 곳부터보다 늘 같거나 많고, 외진 곳부터의 31배 |
| 질문 이해 | 평소 말투 질문 40개(동네·시간·대상·대수·예산·질문 유형)를 정답과 비교 (`tests/intent_cases.json`) | 40/40 |

## 7. 안심하차 Agent가 다른 점

1. **어디에 무엇을 달지까지 알려줘요.** 비어 있는 곳만 찾지 않고, 어디에·무엇을·몇 대 달지와 예산마다 몇 명을 지키는지까지 보여줘요.
2. **세 기관 자료를 한 번에 합쳐요.** 빅데이터센터·제주데이터허브·공공데이터포털 자료의 아이디, 좌표, 글자 형식을 알아서 맞춰요.
3. **자료를 살피고 다시 확인해요.** 자료가 한쪽에 몰렸으면 계산 방법을 바꾸고, 기준·기간·설치 방법을 바꿔도 결과가 그대로인지 확인해요.
4. **숫자를 지어내지 않아요.** 모든 숫자는 정해진 계산식으로 구해서 같은 질문에는 늘 같은 답이 나와요.
5. **보기 쉬워요.** 주변 지도, 걷는 시간, 설치 계획 화면, Agent 분석 흐름 그림, 그림이 든 건의서로 보여줘요.
6. **센터 자료를 넣으면 바로 넓어져요.** 3-03·3-04를 올리면 밤에 내리는 사람과 막차 시간까지, 가로등 자료를 올리면 가로등까지 같은 화면에서 계산해요.
7. **반출·보안 기준을 지켜요.** 10명 미만 숫자는 가리고, 원래 자료는 Claude에 보내지 않고, API가 없어도 끝까지 동작해요.
